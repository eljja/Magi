# oh-my-openmagi 0.1.0 심층 재검증

검증일: 2026-09-25. 대상은 새 패키지의 전체 소스, 설치/감독 CLI, 배포 스크립트, CI와 원본 OmO/OpenCode 연결부입니다. 기존 사용자 설치를 교체하거나 npm에 게시하지 않았습니다.

## 결과

- 패키지 타입 검사와 서식 검사 통과.
- 전체 회귀 테스트 **44개 통과, 160개 assertion**, 실패 0개.
- 최종 배포 tarball 생성, 새 디렉터리 설치, CLI 실행과 플러그인 export 검사 통과.
- 최종 tarball의 OpenCode **1.18.29·1.18.31 통합 시험 모두 통과**. 강화된 검사에서 재시작 전후 매 회차의 실제 task 실행, 잘못된 표의 재시도, 명시적 중지 유지까지 확인했습니다.
- 의존성 감사: 상위 의존성의 문서화된 Low 경고 1건. Moderate/High/Critical 경고는 확인되지 않았습니다. 세부 내용은 아래에 기록했습니다.

## 실제 통합 시험의 조건

VM/컨테이너 대신 새 임시 홈·설정·캐시·데이터·프로젝트·프로세스를 사용합니다. 사용자 홈의 기존 oh-my-magi나 OpenCode 설정은 사용하지 않습니다. npm tarball을 새 디렉터리에 설치한 뒤 그 설치본으로 시험합니다.

Windows에서는 검증용으로 내려받아 버전을 확인한 네이티브 OpenCode 바이너리를 직접 실행합니다. 실행 파일은 재사용할 수 있지만 각 실행의 홈·설정·세션 데이터·캐시·프로젝트는 새 임시 경로로 분리합니다. 초기 설치에 사용한 Bunx 런처가 반복 재시작 시 프로세스 생성 전에 실패하는 사례를 확인했기 때문입니다. 서버 health 응답의 실제 버전도 단언합니다. 제품 감독기의 실행 실패 재시도는 별도의 실제 프로세스 시험으로 확인했습니다.

각 버전에서 원본 oh-my-opencode@4.19.4를 먼저 실행하여 에이전트 정의를 얻고, 같은 격리 시험 환경에서 OpenMagi를 실행해 기존 정의 전체가 그대로인지 비교합니다. 이후 실제 의회 세션, 원본 task → explore → read, 독립 검증 명령, 정기 보고, 한국어 보고 간격 조정, 프로세스 종료/재시작과 명시적 중지 유지까지 검사합니다. 최소 버전에서는 실제 백그라운드 task와 결과 회수 경로를 사용합니다.

모델 서버만 결정적인 로컬 fixture입니다. 지정한 Casper의 첫 최종 표를 잘못된 JSON으로 응답하게 하여, 표가 유효하지 않은 동안 실행하지 않고 해당 멤버를 재시도한 뒤 계속 진행하는지 확인합니다. 시험 코드의 멤버 선택은 전체 본문의 다른 이름이 아니라 최종 투표 헤더를 정확히 매칭합니다. 또한 시험 모델이 과거 회의 요약의 background ID를 새 업무의 ID로 재사용하지 않도록 수정했고, 검증을 통과한 매 회차에 실제 task 실행 증거가 있는지 단언합니다. 이전 ID를 조회해 Task not found를 받는 시험 경로는 성공으로 인정하지 않습니다.

최종 검사는 같은 tarball 설치본으로 수행했습니다. 보고 건수는 시험 중 실제 생성된 기록 수이며 시험의 소요 시간에 따라 달라집니다.

| 실제 OpenCode 버전 | 위임 방식                           | 원본 에이전트 정의 비교 | 검증된 회차 | 보고 기록 | 장애 복구·중지 유지 |
| ------------------ | ----------------------------------- | ----------------------- | ----------- | --------- | ------------------- |
| 1.18.29            | 백그라운드 task + background_output | 전체 일치               | 2           | 4         | 통과                |
| 1.18.31            | 동기 task                           | 전체 일치               | 2           | 1         | 통과                |

## 의존성 감사의 남은 경고

격리된 최종 패키지 설치에 대해 bun audit를 실행했습니다. 상위 OmO/OpenTUI 의존성에 포함된 @babel/core@7.28.0에서 [GHSA-4x5r-pxfx-6jf8 / CVE-2026-49356](https://github.com/babel/babel/security/advisories/GHSA-4x5r-pxfx-6jf8)가 보고됩니다. 공식 분류는 Low, CVSS 3.2이며 수정 버전은 7.29.6입니다.

공식 설명에 따르면 공격자가 입력 소스를 제어하고 출력 코드를 읽을 수 있으며 대상 source map의 경로를 알 때 악성 sourceMappingURL로 정보가 노출될 수 있습니다. OpenMagi의 새 서버/CLI 코드는 Babel을 호출하거나 추가 UI를 빌드하지 않습니다. 다만 의존성이 설치되어 있다는 사실은 남으므로 감사 결과를 0건으로 표시하지 않습니다.

원본 OmO 4.19.4를 유지하는 이번 릴리스에서는 이 경고를 공개된 상위 의존성 예외로 기록했습니다. 배포 검사에 추가한 script/audit.ts는 이 정확한 Low 경고만 구별하고, 새 경고 또는 더 높은 심각도가 생기면 실패합니다. 상위 패키지의 의존성 갱신 시 제거할 예외입니다. 작업 대상 프로젝트에서 신뢰하지 않는 코드를 Babel로 컴파일하는 경우에는 해당 프로젝트의 Babel 갱신 또는 공식 inputSourceMap 완화책을 별도로 적용해야 합니다.

## 검증의 범위

이번 결과는 Windows/Bun 1.3.13에서 수행한 코드 검토, 실제 프로세스 및 로컬 모델 fixture 통합 시험입니다. Linux/macOS 호환성 작업은 CI에 구성했으며 이 로컬 작업에서 실행됐다고 주장하지 않습니다. 실제 유료 LLM의 수일간 운전, 운영 기기의 재부팅/서비스 등록, GUI 파일 뷰어의 자동 갱신은 이 결과에 포함되지 않습니다.

임의의 외부 API/셸 부작용에 대한 보편적인 exactly-once 보장이나 전원·디스크·권한 부재 중의 실행은 보장하지 않습니다. 기록을 보존하고 상태를 확인한 후 재개하는 설계이며, 도구 경로 보호는 OS 보안 경계를 대체하지 않습니다. 누적 원본 이력의 디스크 사용량은 계속 증가합니다.

npm 게시, 글로벌 설치 교체와 OS 서비스 등록은 수행하지 않았습니다.
