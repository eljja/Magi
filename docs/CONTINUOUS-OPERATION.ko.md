# 지속 운영과 사용자 편의성 — 2026-09-20

목표는 **하나의 목표를 세 인격의 논의와 표결로 계속 발전시키고 사용자가 필요한 때 개입하는 것**입니다. 기본 `continuous` 모드에는 별도의 완료 표결이 없습니다.

## 실제 흐름

1. OpenCode에서 **Magi**를 선택하고 목표를 평소처럼 말합니다.
2. MELCHIOR·BALTHASAR·CASPER가 각자 의견을 낸 뒤 서로의 의견을 읽고 최종 투표합니다. 세 명의 유효한 표를 모두 받은 다음 실행 승인 정책을 적용합니다.
3. 승인한 방향을 공식 OmO의 Sisyphus와 전문 에이전트가 실행합니다.
4. 의미 있는 진전, 실험 결과, 문제 또는 자연스러운 작업 전환 시점에 실행 결과와 검사 결과를 기록합니다. `magi_submit`은 선택 사항입니다. 진행 중인 하위 작업이 있으면 결과를 기다립니다.
5. 별도의 완료 회의를 열지 않고 이 증거를 다음 계획 회의로 넘깁니다. 실패는 다음 수정의 근거이며, 통과는 목표 전체의 완료 선언이 아닙니다.

목표·회의 횟수에 상한이 없습니다. 작업자가 활동하면서 끝없이 재조사하는 경우까지 이 변경이 해결했다고 주장하지 않습니다. 반복 증거 정체 감지와 복구는 유지합니다. 호스트·모델·권한 등 실제 실행 조건이 막히면 진행할 수 없습니다.

기존 설정에 `selfImprovement.mode: "complete"`가 명시돼 있다면 완료 검토 방식이 유지됩니다. 지속 운영을 원하면 `continuous`로 바꾸세요. 기존 회의와 로드맵 기록은 지우지 않습니다.

## 언제 무엇을 보고하나

| 조건 | 동작 |
| --- | --- |
| 지난 보고 이후 약 4시간 실제 가동 | 진행·검사·미해결 사항·현재 상태를 보고합니다. 진전이 없어도 없다고 보고합니다. |
| 세 인격 모두 이미 발생한 큰 변화라고 판단 | 다음 계획 회의의 최종 의견에 각자 근거를 남기면 조기 보고합니다. 단순한 실행 찬성 3표와 구분합니다. |
| 모델이나 작업이 아직 진행 중 | 보고 타이머는 독립적으로 동작합니다. 보고 때문에 작업을 중단하지 않습니다. |
| 대화에 보고를 전달하지 못함 | 로컬 파일을 남기고 같은 보고 ID로 재시도합니다. 실행 루프를 중지하지 않습니다. |

보고는 `.magi/LATEST-REPORT.md`, `.magi/reports/msg_*.md`, 목표를 처음 말한 OpenCode 대화에 남습니다. 별도의 모델 호출 없이 실제 기록을 구성하며 **자동 진행 보고**라고 표시합니다. OpenCode의 메시지 API를 사용한 대화 기록이므로 사용자 메시지 형태로 표시될 수 있지만, 사용자 지시로 수집하거나 목표로 실행하지 않습니다.

서버가 활성 상태로 관측된 구간만 누적합니다. 일시 중지·재시작 사이의 긴 공백은 제외하고 저장된 가동 시간을 이어갑니다. 4시간은 보고 간격이며 작업 시간 제한이나 의회 회의 간격이 아닙니다.

```jsonc
{
  "selfImprovement": { "mode": "continuous" },
  "reporting": { "intervalMs": 14400000, "notifySession": true }
}
```

대화 기록을 원하지 않으면 `notifySession: false`로 바꿉니다. 로컬 보고는 유지됩니다. 매분 보관되는 상태 스냅샷은 상세 진단 기록이며 사용자 알림과 다릅니다. 보고마다 최근 진행 기록 24건을 요약하고 전체 회의와 증거는 원문 기록에 남깁니다.

## 실시간 감시와 일반 대화

- **브라우저:** `.magi/index.html`에서 인격별 독립 의견, 최종 표와 이유, 큰 변화 판단, 현재 실행, 최근 보고를 확인합니다. 서버 저장과 페이지 새로고침이 각각 15초이므로 반영까지 보통 15~30초입니다.
- **터미널 TUI:** 패널이 2초마다 갱신됩니다. 명령 팔레트의 `Open Magi Live Monitor`는 브라우저 감시 페이지를 엽니다.
- **CLI:** `oh-my-magi monitor --project <폴더>`로 감시 페이지를 엽니다. `--no-open`은 주소만 출력합니다. 소스 설치에서는 패키지 폴더에서 `bun bin/cli.ts monitor --project <폴더>`를 실행합니다.
- **개입:** 목표를 말한 대화에 우선순위나 제약을 평소처럼 말합니다. 질문은 다음 작업 변경 지시로 자동 확대하지 않습니다. 명시적으로 중지·재개를 요청할 수 있습니다.

CLI·TUI·웹·데스크톱은 동일한 서버 에이전트와 대화 API를 사용합니다. TUI 패널은 터미널 전용이며 웹·데스크톱에는 전용 Magi 위젯을 주입하지 않습니다. 별도 로컬 감시 페이지와 원래 대화의 보고를 사용합니다. 원격 서버에서는 서버 쪽 보고 파일에 접근해야 합니다. 원격 TUI 파일 동기화는 제공하지 않습니다.

## 설치와 의존성

정식 이름은 **oh-my-magi**입니다. `omm`은 이 프로젝트의 별칭일 뿐, npm의 `omm`은 관계없는 패키지입니다.

```sh
opencode plugin oh-my-magi --global
```

위 명령은 npm에 공개된 최신 버전을 설치합니다. **점검 시점의 공개 버전은 0.1.0이며 이 문서의 개선은 아직 게시되지 않은 0.1.1 소스입니다.** 현재 기능이 필요하면 소스 빌드 후 `opencode plugin /절대경로/Magi/packages/oh-my-magi --global` 또는 README의 로컬 설치 도구를 사용하세요.

OpenCode의 패키지 설치기가 `dependencies`를 설치합니다. OMM은 공식 OmO의 npm 배포인 **`oh-my-opencode@4.19.4`를 정확한 의존성으로 포함**하며, 별도로 OmO를 먼저 설치할 필요가 없습니다. 실행 시 실제 OmO 서버 플러그인·실행 에이전트·`task` 도구를 확인합니다. 누락된 의존성은 OMM 재설치로 복구하며, 실행 중 임의로 다른 최신 OmO를 내려받아 교체하지 않습니다.

기존 OmO 등록은 백업 후 중복을 제거하고 모델·에이전트 설정을 보존합니다. 시작 시 기존 등록을 바꿨다면 한 번 재시작해야 합니다. 인식되지 않는 사용자 정의 플러그인 래퍼는 별도 확인이 필요합니다. 모델 계정·API 인증은 OpenCode에서 연결해야 하며 플러그인이 계정을 자동 생성하지 않습니다. Git 설치·저장소 초기화는 필수가 아닙니다.

지원 기준은 OpenCode 1.18.29 이상, 현재 확인한 최신 버전은 1.18.31입니다. 주간/변경 시 CI에서 최소·최신 버전을 검사하고, SDK·OmO 갱신 후 실제 통합 검사를 다시 실행합니다. 아직 출시되지 않은 버전의 호환성을 보장하지 않습니다.

## 검증 기록과 남은 범위

검사 항목: 완료 표결·필수 제출 없이 다음 회의로 진행, 실패 검사의 정직한 전달, 4시간 경계·일시 중지·호스트 공백, 3인 근거 합의와 중복 보고 방지, 전달 실패 복구, 부분 의견 표시와 HTML 이스케이프.

109개 테스트·525개 검증 조건과 타입 검사·빌드·패키지 생성을 통과했습니다. 실제 Windows OpenCode **1.18.29와 1.18.31**, OmO 4.19.4에서 네이티브 `plugin` 설치, 서버/TUI 등록, 기존 OmO 이전·재시작, Git 없는 실행, 실제 `task → explore → read`, 3회 연속 진행, 완료 표결 없는 연결, 원래 대화의 주요 변화 보고, 일반 대화 개입과 중지·재개를 통과했습니다. 이 검사는 **실제 프로그램과 재현용 모델 응답**을 사용합니다. 4시간 경계는 저장 상태와 시간을 조절해 검사했으며 4시간 실제 모델 장기 운전 시험으로 표현하지 않습니다.

빈 소비자 폴더에 npm으로 압축 패키지를 설치해 별도 OmO 선행 설치 없이 OMM 0.1.1, OmO 4.19.4, SDK/plugin 1.18.31이 함께 설치되는 것을 확인했습니다. Windows에서 별도로 시도한 Bun 소비자 설치는 캐시 폴더 이동의 `EPERM`으로 실패했고 npm 설치는 성공했습니다. 이 캐시 문제는 플러그인이 로드되기 전의 설치기 단계이며 OMM이 자동 복구했다고 표현하지 않습니다. 따라서 모든 PC의 무조건적인 설치 성공을 보장하지 않습니다.

과거 무료 모델의 코드 수정·테스트 통과 기록은 [실제 모델 감사](REAL-MODEL-AUDIT.ko.md)에 남깁니다. 이번 완료 표결 제거로 과거 실행 결과를 성공으로 소급 변경하지 않습니다. 새 구조의 장시간 실제 모델 실행, 모든 데스크톱/TUI 조작과 재접속, npm 0.1.1 공개 배포는 별도로 확인해야 합니다.

브라우저 도구가 로컬 `file://` 페이지 열기를 보안 정책으로 차단해 이번 감시 페이지의 시각 검증은 완료하지 못했습니다. 생성 HTML의 내용·부분 의견·이스케이프 검사와 실제 OpenCode 대화 API 보고 전달은 별도로 검증했습니다. 사용자가 로컬 브라우저에서 직접 여는 기능과 도구의 접근 제한은 구분합니다.
