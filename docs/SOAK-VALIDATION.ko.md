# GUI와 실제 모델 장시간 운전 검증 — 2026-09-20

현재까지 **실제 모델 4시간 운전 통과 판정은 없습니다.** 최신 설치·CLI·웹·데스크톱 평가는 [전체 실측 결과](END-TO-END-AUDIT.ko.md)를 참고하세요.

## 현재 확인한 내용

- 공개 버전은 `oh-my-magi@0.1.1`, 실제 런타임은 OpenCode 1.18.31과 OmO 4.19.4입니다. 이 공개 버전의 [최소·최신 버전 및 3개 운영체제 CI](https://github.com/eljja/Magi/actions/runs/35451257603)가 모두 통과했습니다. 이후 소스 수정의 검증은 전체 실측 문서에서 구분합니다.
- 최종 압축 패키지를 사용한 별도 GUI 시험 서버에서도 네이티브 설치, 3회 이상 연속 진행, 완료 표결 없는 연결, 세 인격의 주요 변화 보고와 원래 대화 전달, 중지·재개를 확인했습니다. 이 단계의 모델은 재현용 응답입니다.
- 사용자의 명시적인 웹 GUI 검증 허용 후 Chrome에서 공식 OpenCode 웹 앱을 확인했습니다. 에이전트 선택 메뉴에 Magi와 OmO 실행 에이전트가 함께 표시됐고, 기존 대화에 세 인격의 주요 변화 보고가 표시되는 것을 실제 화면으로 확인했습니다. 이후 공식 Windows 데스크톱 1.18.31의 서명된 배포본도 격리 실행했으나 플러그인 설치 전에 로고 화면에서 진행되지 않았습니다. 일반 설치 마법사와 데스크톱 Magi 사용은 통과로 표시하지 않습니다.
- 실제 Nex 모델의 한국어 목표 접수, 상태·3인 투표 조회, 자연어 중지·재개를 웹 GUI에서 확인했습니다. 재개는 설명 문장만 확인한 것이 아니라 `loopActive` 복귀와 다음 회의 시작을 대조했습니다. CLI에서도 Magi 대화와 상태 명령, 자동 보고 표시를 확인했습니다.
- 로컬 감시 HTML의 기존 접근 차단은 우회하지 않았습니다. OpenCode 웹 앱 검증의 허용과 로컬 감시 파일의 시각 검증은 별개입니다. 데스크톱 전용 앱과 로컬 감시 HTML의 직접 화면 검증은 남아 있습니다.
- npm 추가 인증은 로그인된 Chrome에서 사용자가 완료했습니다. 실제 게시 명령이 성공으로 종료된 뒤 npm의 처리 대기를 거쳐 `oh-my-magi@0.1.1`과 `latest`를 공개 조회했습니다. 직접 내려받은 패키지의 SHA-256이 검토한 배포 후보와 일치합니다. [게시 확인 기록](RELEASE-AUDIT.md#publication-011)을 참고하세요.
- 공개 후 npm 패키지 이름으로 빈 OpenCode 환경에 설치한 검사도 통과했습니다. `magi-smoke-gQaCle`에서 OmO 자동 의존성 설치, Git 없는 실행, 연속 회의·실제 위임·보고 전달을 확인했습니다. 이 짧은 검사는 재현용 모델을 사용했고 진행 중인 실제 모델 시험을 대체하지 않습니다.
- OpenRouter의 계정 API와 현재 모델 목록을 확인했습니다. `nex-agi/nex-n2.5-mini:free`는 도구 호출을 지원하며 입력·출력 가격이 모두 0입니다. 사전 확인 당시 계정 사용액은 0, 무료 요청 잔여량은 880회였습니다. 다른 실행이나 날짜 변경에 따라 잔여량은 달라집니다.

## 장시간 시험 방식

`packages/oh-my-magi/script/live-smoke.ts`에 장시간 관찰 모드를 추가했습니다. 제품의 실행 횟수나 목표 유지 시간을 제한하는 설정이 아닙니다. 격리한 시험 프로젝트와 무료 모델만 사용하며, 실제 사용자 프로젝트의 모델 설정을 덮어쓰지 않습니다.

기본 관찰 시간은 **270분(4시간 30분)**입니다. 짧은 시험의 성공 조건인 3회 연속 회의와 실제 검사 통과에 도달해도 종료하지 않습니다. 다음 증거를 함께 확인해야 장시간 시험을 통과로 기록합니다.

1. 지정한 실제 경과 시간을 관찰하고, 살아 있는 런타임의 상태 갱신을 최소 4시간 확인합니다. 호스트가 멈췄거나 잠든 공백은 가동 시간으로 부풀리지 않습니다.
2. 세 인격의 논의·표결을 거쳐 실제 OmO `task → explore → read`가 실행되고, 진행 증거가 다음 회의로 이어져야 합니다.
3. 정기 또는 주요 변화 보고가 실제로 전달돼야 합니다. 보고 후에도 루프가 활성 상태이며, 더 뒤의 회의에서 새 진행 결과가 기록돼야 합니다.
4. 시험 프로젝트 밖에 별도로 보관한 원본 시험 파일로 최종 구현을 다시 검사합니다. 모델이 자체 테스트를 약화한 결과를 성공으로 인정하지 않습니다.

진행 중 `soak-observation.json`에 실제 경과 시간·관측 가동 시간·보고 시점·보고 이후 진전을 저장합니다. `progress.json`, `provider-calls.json`, `result.json`, 원래 회의록·보고 파일과 함께 판정 근거로 사용합니다. 인증 값은 결과 파일에 넣지 않습니다.

무료 요청 잔여량 소진, 공급자 오류, 런타임 중단, 사용자 중지 또는 시험 시간 종료를 구분합니다. 유료 모델로 자동 전환하지 않으며, 할당량 때문에 4시간에 못 미치면 장시간 성공으로 표시하지 않습니다. 보고 간격은 제품 기본값인 4시간을 유지하고 시험 시간을 조작해 보고를 발생시키지 않습니다.

장시간 시험에서는 시작 시 무료 요청 잔여량에 맞춰 시험용 프록시의 요청 간격을 정합니다. `allowance.json`에 요청 상한과 간격을 기록합니다. 이는 공급자 할당량 관리이며, 제품의 회의·목표 반복 제한이 아닙니다. 기본 짧은 시험은 기존 6.5초 간격을 유지합니다.

## 실행 예

패키지 폴더에서 PowerShell로 실행합니다. API 키는 시작 후 숨김 입력으로 받고 명령줄·설정 파일에 직접 적지 않습니다.

```powershell
$env:MAGI_LIVE_SOAK='true'
$env:MAGI_LIVE_MINUTES='270'
$env:MAGI_LIVE_MODEL='nex-agi/nex-n2.5-mini:free'
$env:MAGI_OPENCODE_BIN='C:/실제/경로/opencode.exe'
bun run smoke:live
```

공개 npm 버전을 검증할 때에는 게시 확인 후 `MAGI_PLUGIN_SPECIFIER='oh-my-magi@0.1.1'`을 지정합니다. 기본값은 현재 로컬 패키지입니다. `MAGI_LIVE_PREFLIGHT='true'`는 인증·모델 가격·잔여량만 확인하고 모델 과제를 시작하지 않습니다. 실제 시험에서는 이 변수를 제거해야 합니다.

시험 산출물 폴더의 `STOP-TEST` 파일로 시험을 종료할 수 있습니다. 이는 사용자가 운영하는 다른 Magi 목표에 영향을 주지 않습니다. 시험 종료 시 시험용 목표와 자식 프로세스를 정리합니다.

## 실제 시험 기록

예비 실행 `magi-openrouter-live-4bLLy0`에서는 실제 세 인격의 독립 의견·상호 검토·최종 찬성 3표, 실제 OmO 위임을 확인했습니다. 약 3분·25요청 후 요청 간격을 조정하기 위해 시험을 중지했습니다. 이때 원본 구현 검사는 실패했고 전체 성공으로 기록하지 않습니다.

`magi-openrouter-live-cNI2rs`는 한국 시간 01:18에 시작해 약 **30분, 45요청** 후 종료했습니다. 첫 회의가 경로 표기와 중복 결정 도구 오류 때문에 반복됐고 원본 검사는 실패했습니다. GUI의 자연어 중지 기능을 검사하기 위해 의도적으로 중지했습니다. 당시 시험기의 `loop-stopped-unexpectedly` 판정은 이 수동 GUI 검사를 알지 못한 결과이며, 원인 미상의 제품 중단으로 해석하지 않습니다. 시작·종료 계정 사용액은 모두 0입니다.

`magi-openrouter-live-irMYjo`에서는 GUI에서 Magi를 선택하고 일반 목표를 입력해 실제 의회와 OmO 위임까지 확인했습니다. 16요청 뒤 OpenRouter 옵션을 바로잡기 위해 종료했습니다. 전체 경과 약 22.5분에는 목표 입력 전 UI 검사 대기 시간이 포함됩니다. 원본 검사는 실패했으며 성공 운전으로 계산하지 않습니다.

수정 소스의 `magi-openrouter-live-ZeSvNG`에서는 OpenRouter에 `parallel_tool_calls: false`가 실제 전송되는 것, 세 인격의 승인과 OmO 위임, GUI 상태·투표 조회, 중지·재개를 확인했습니다. 약 12.3분, 80요청 뒤 **시험 예산**에 도달해 종료했습니다. 당시 공급자 무료 잔여량은 727회였으며 공급자 한도 소진과 다릅니다. 자동 보고 3회와 다음 회의는 확인했지만 원본 행동 검사는 1개 통과·2개 실패했습니다. 이 시험만 보고 간격을 2분으로 바꿨으며 **4시간 기본 간격의 장시간 시험으로 계산하지 않습니다.** `MAGI_LIVE_INTERACTIVE=true`는 GUI에서 빈 대화를 만들고 목표를 입력하거나 중지·재개할 수 있게 하며, `MAGI_LIVE_AUTOSTART=true`를 함께 사용하면 목표를 자동 입력합니다.

자동 후속 점검 등록은 자동 승인 검토에서 거절돼 별도 허용을 요청한 상태입니다. 예약 점검이 등록됐다고 가정하지 않습니다.

최종 단기 개발 검사 `magi-openrouter-live-gPzD4n`은 **14.5분, 69요청**을 사용했습니다. 실제 코드·테스트·문서 변경과 별도 원본 검사 3개 통과, 진행 기록 저장 및 두 번째 회의 시작을 확인했습니다. 그러나 모델이 병렬 호출 금지 옵션을 무시해 중복 결정 도구 호출이 재발했고, 재시도에서도 반복돼 검토를 위해 종료했습니다. `stopped-for-inspection`은 연속 운전 성공이 아닙니다. 원본 검사 종료 코드는 0이며, API 계정 사용액도 시작·종료 모두 0입니다. 시험기는 두 번째 회의에서 미리 정의한 일반 대화 지시를 보내므로, 사용자 개입이 전혀 없는 순수 내구성 검사와도 구분합니다. 핵심 증거는 `.tmp/omm-integration/evaluation-live-gPzD4n/`에 복사했습니다.

현재 로컬 OpenCode/Magi 운전 시험 프로세스는 종료했습니다. **진행 중인 4시간 시험이나 자동 후속 점검은 없습니다.** GitHub CI 상태는 연결된 실행에서 별도로 확인합니다.

## GUI에서 확인한 추가 개선 항목

- 현재 보고는 OpenCode 사용자 메시지 형태로 표시되며 Markdown 제목 기호가 그대로 보입니다. 수정 소스에서는 제출 데이터의 내부 JSON 대신 요약·산출물·미해결 사항을 표시합니다.
- 폴더 선택기가 경로를 탐색하면서 중간 디렉터리의 OpenCode 인스턴스를 초기화합니다. 이 과정에서 `.magi`·`.omo` 설정 파일이 생성되는 부작용을 확인했습니다. 목표를 시작하지 않은 탐색 경로에 대한 파일 쓰기와 초기화 비용을 줄이는 후속 검토가 필요합니다.
- Markdown 표시·초기화 문제를 모두 해결했다고 주장하지 않습니다. 공개 패키지와 수정 소스의 실행 기록을 구분합니다.
