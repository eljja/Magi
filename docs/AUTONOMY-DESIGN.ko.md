# 세 인격 기반 자율 개발 개선 — 2026-09-19

목표는 **공식 OmO 위에서 하나의 사용자 목표를 계속 발전시키는 Magi 의회**입니다. 세 인격은 서로 다른 관점·세션·판단 이력을 가진 에이전트이며, 의식이나 독립된 학습 가중치를 갖는다는 뜻은 아닙니다. 같은 모델을 세 역할에 사용할 수도 있고, 역할마다 다른 모델을 지정할 수도 있습니다.

## 실행 구조

1. OpenCode에서 `magi`를 선택하고 목표를 말합니다. 이 대화는 목표 접수·상태 설명·사용자 개입을 담당합니다.
2. 제안 담당이 돌아가며 다음 작업을 제안합니다. Melchior는 구조와 과학적 타당성, Balthasar는 실패와 위험, Casper는 사용자 의도와 실질적 가치를 평가합니다.
3. 세 인격이 **분리된 세션에서 먼저 독립 의견**을 냅니다. 그다음 서로의 의견을 읽고 반박·수정한 뒤 **각자 최종 투표**합니다.
4. 세 명의 유효한 최종 투표가 모두 있어야 다수결 또는 설정한 만장일치를 적용합니다. 안전상 중대한 거절은 기본 정책에서 실행을 막습니다. 한 명이 응답하지 않았다고 두 표만으로 통과시키지 않습니다.
5. 승인된 작업은 새로운 **OmO 실행 하위 세션**으로 보냅니다. 공식 Sisyphus와 `task`, 전문 에이전트, 도구를 사용합니다. 사용자 대화의 “접수만 하라”는 지시가 실행 대화에 섞이지 않습니다.
6. 실제 도구 결과·산출물 보고·검증 명령을 확인합니다. 독립 리뷰는 현재 마일스톤을 검토하며, 기계적 검증과 리뷰가 모두 통과해야 완료로 기록합니다.
7. 실패 원인과 실제 증거를 다음 회의로 넘깁니다. 초기 계획을 마쳐도 같은 목표의 다음 연구·개선을 제안합니다. **목표 사이클과 회의 라운드의 횟수 제한은 없습니다.**

| 회의 진행 중 화면에는 도구 0회만 표시                 | 인격별 요청·완료·오류·모델·시도·갱신 시각을 별도로 표시합니다. 요청 중이라는 사실을 작업 진척으로 포장하지 않습니다.                                               |
| Windows에서 보고서를 열어 둔 동안 파일 교체 실패      | 상태·보고서·로드맵·요약 기억 저장에 원자적 교체와 일시적 파일 잠금 재시도를 적용했습니다.                                                                          |

완료된 의견은 즉시 `COUNCIL.md`에 공개 판단으로 남습니다. 모델의 비공개 추론 과정은 요청하거나 회의록으로 저장하지 않습니다. 오래된 원문은 보존하되 다음 요청에 넣는 문맥은 제한하므로, 무한 반복이 매번 전체 회의록을 읽는 방식은 아닙니다.

실제 모델 시험에서는 고정된 첫 “환경 조사” 단계가 구현을 미루는 원인이 됐습니다. 새 목표의 기본 로드맵은 이제 사용자 요청의 결과물 하나를 담고, 의회가 그 안의 조사·수정·실험을 선택합니다. 조사 보고서만으로 개발 요청을 완료할 수 없으며 기존 검사 실패를 해결해야 독립 승인을 받을 수 있습니다. 기존 저장 로드맵과 사용자가 명시한 마일스톤은 보존합니다.

후속 보완으로 빈 근거를 반환한 제안·투표를 거부하고, 승인 작업에 실제 검증 실행 파일 경로를 전달했습니다. 터미널 패널은 진행 중인 회의 요청과 오류를 보여 주며, 실행 하위 세션을 보고 있어도 목표 소유 대화에 중지·재개를 전달합니다. 외부 CLI에서 기록한 중지도 서버가 실행 세션과 그 하위 작업에 적용합니다. 다른 대화의 작업을 중지하지 않습니다. 새 `.magi/.gitignore`에는 인격별 기억·요약·사용자 대화 이력도 포함됩니다.

실제 OmO 백그라운드 위임에서 추가 경쟁 상태를 발견했습니다. 부모가 결과를 기다리며 잠시 `idle`이 된 뒤 OmO가 다시 깨우는 사이에 OMM이 다음 회의를 시작할 수 있었습니다. 이제 백그라운드 작업을 사용한 실행은 부모 응답과 하위 작업의 마지막 갱신 후 30초가 지나야 검토하며, 독립 검토 도중 새 응답이나 실행이 생기면 그 검토를 폐기하고 기다립니다. 새 응답에는 이전 응답의 검증 캐시를 재사용하지 않습니다. 이는 실행 종료를 확인하는 대기 구간이며 회의·목표 반복 횟수 제한이 아닙니다.

## 사용자 운영

실제 카테고리 위임 검사를 추가하면서 OmO 4.19의 설정 형식 결함도 수정했습니다. OpenCode 전용 옵션은 `"[opencode]"`에 기록해야 하며, 대괄호 없는 기존 키는 전체 설정을 거부하게 했습니다. OMM은 이전 프로젝트 설정을 백업·변환하고 프로필·모델·주석을 보존합니다. 지정하지 않은 기본 모델 호출을 거부하는 실제 OmO 카테고리 검사로 이를 검증합니다.

일반 대화로 우선순위와 제약을 바꿀 수 있습니다. “왜 이 방법이야?” 같은 질문은 변경 승인으로 취급하지 않습니다. 작업 중에는 새 지시를 다음 회의에 반영하며, 즉시 멈춰야 할 때는 같은 대화에서 중지를 요청하거나 `/magi stop`을 사용합니다. 실행이 별도 세션이어도 그 하위 전문 에이전트까지 중지 대상에 포함됩니다.

`.magi/index.html`은 15초마다 갱신됩니다. `STATUS.md`에는 사용자 대화와 현재 OmO 실행 세션 ID가 표시됩니다. `COUNCIL.md`는 회의 원문, `members/`는 인격별 판단 이력, `reports/`는 분 단위 보고, `USER-GUIDANCE.md`는 사용자 대화 이력입니다. Git 저장소 없이도 동작합니다.

기본 모델 요청 제한 시간은 3분, 실행 정체 판단 시간은 30분입니다. `.magi/config.jsonc`의 `resilience.timeoutMs`, `stallTimeoutMs`로 조정할 수 있습니다. 이는 개별 요청·정체 복구 설정이며 목표나 회의의 반복 횟수 제한이 아닙니다. 제공자 장애에는 대기 후 재시도합니다. OpenCode 서버·PC·모델 제공자가 꺼져 있는 동안에는 진행할 수 없습니다.

## 검증과 재현

백그라운드 경쟁 상태의 회귀 검사까지 포함해 **97개 테스트·429개 검증 조건**, 타입 검사와 빌드가 통과했습니다. OmO 설정 수정판 `c665da7`은 실제 Windows OpenCode 1.18.29·1.18.31 / 공식 OmO 4.19.4의 결정적 통합 시험과 [Linux·macOS·Windows 최소/최신 버전 6개 조합 및 코어 검사](https://github.com/eljja/Magi/actions/runs/35381730558)를 모두 통과했습니다. CI 커밋 이후 추가한 실행 종료 대기 검사는 별도로 구분합니다. 이는 실제 모델의 과제 완수 판정과도 구분합니다.

`packages/oh-my-magi`에서 다음 명령을 실행합니다.

```sh
bun test
bun typecheck
bun run build
bun run smoke
```

`smoke`는 실제 OpenCode와 공식 OmO를 실행하지만 모델 응답만 재현 가능한 테스트 서버가 제공합니다. 사용자 대화와 OmO 하위 세션을 모두 따라가며, 실제 `task → explore → read`, 세 사이클, 대화 개입, 중지 후 새로운 실행, 회의·보고 파일을 검사합니다.

추가한 `task(category: deep) → Sisyphus-Junior → read` 검사도 설정 수정 후 OpenCode 1.18.29와 1.18.31에서 통과했습니다. 테스트 제공자의 Hephaestus에는 upstream이 요구하는 GPT 계열의 가상 모델 이름을 명시해 등록 여부만 확인하며, 그 모델을 호출하면 시험이 실패합니다. 실제 무료 모델에서 Hephaestus가 모델 제약으로 비활성화되는 것을 우회하지 않습니다.

실제 OpenRouter 무료 모델 시험은 별도로 실행합니다. 먼저 [현재 무료 모델 목록](https://openrouter.ai/models?max_price=0)에서 도구를 지원하는 모델을 선택합니다. PowerShell 예시는 다음과 같습니다.

```powershell
$env:MAGI_LIVE_MODEL = '선택한/모델:free'
# 필요할 때만 실제 OpenCode 실행 파일 경로를 지정합니다.
$env:MAGI_OPENCODE_BIN = 'C:/경로/opencode.exe'
bun run smoke:live
```

API 키는 실행 후 숨김 입력으로 받거나 `OPENROUTER_API_KEY` 환경변수로 전달합니다. 키를 소스나 설정 파일에 넣지 않습니다. 로컬 시험 게이트웨이만 실제 키를 보관하며, 모델 작업 프로세스에는 가짜 게이트웨이 인증 값만 전달합니다. 카탈로그의 입력·출력 가격이 0인 `:free` 모델만 허용하고 요청에도 가격 상한 0을 적용합니다. 모델 응답을 만들어 내거나 성공 결과로 바꾸지 않습니다.

시험은 임시 폴더에 작은 버그 과제를 만들고, **시험 자체에만** 20분·최대 80요청의 예산을 둡니다. 실제 자율 루프의 제한이 아닙니다. 중간 종료는 출력된 시험 폴더에 `STOP-TEST` 파일을 만들면 됩니다. 시험 종료 시 해당 서버와 하위 프로세스를 정리합니다. 원본 행동 테스트는 작업 폴더 밖에 별도로 보존해, 작업자가 테스트를 약화했어도 최종 판정을 속이지 못하게 합니다.

성공에는 실제 위임·하위 에이전트의 읽기, 검증된 마일스톤, 후속 사이클, 보존된 원본 테스트 통과가 필요합니다. 인증·HTTP 200·투표 완료·도구 호출 횟수만으로 성공 처리하지 않습니다. `result.json`, 공개 응답·도구 기록, 회의록, 검증 로그가 시험 폴더에 남습니다.

현재 실제 모델별 판정과 출시 상태는 [실제 모델 감사](REAL-MODEL-AUDIT.ko.md)를 확인하세요. 유한한 검사가 장기간 무중단 실행이나 모든 모델의 개발 능력을 보장하지는 않습니다. npm에 공개된 0.1.0에는 이 개선이 없으며, 0.1.1 게시 전에는 현재 소스를 빌드해 설치해야 합니다.
