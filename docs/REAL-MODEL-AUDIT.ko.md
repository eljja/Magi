**2026-09-19 후속 개발:** [세 인격 기반 자율 개발 설계와 수정 내용](AUTONOMY-DESIGN.ko.md)을 추가했습니다. 구조화된 결정과 실행 세션 분리 후 실제 무료 모델에서 제안·세 명의 독립 의견·상호 검토·최종 찬성 투표·공식 OmO 전문 에이전트 위임을 확인했습니다. 아래의 실패 기록은 이전 구현의 결과이며 삭제하지 않았습니다. 후속 모델 시험의 전체 구현·검증 성공 여부는 이 문서의 후속 결과에서 별도로 구분합니다.

이 문서는 테스트용 모델 서버를 사용한 기존 [사용 흐름 점검](USER-FLOW-AUDIT.ko.md)과 별개입니다. 실제 OpenCode에 OpenRouter 인증을 연결하고 무료 모델의 응답으로 Magi를 실행했습니다. **API 연결 성공만으로 자율 개발이 검증됐다고 판단하지 않습니다.**

**판정: 실제 무료 모델을 이용한 자율 개발 전체 흐름은 미통과입니다.** 최신 Nex 시험에서는 의회 승인 후 실제 OmO가 코드를 수정했고 보존한 원본 테스트 3개도 통과했습니다. 그러나 Magi의 독립 완료 검토와 후속 회의까지 마치는 전체 성공 조건에는 도달하지 못했습니다. 아래에는 수정 전 실패와 수정 후 부분 성공을 모두 남깁니다. 공개 배포 전의 실제 모델 전체 검증을 통과했다고 표시해서는 안 됩니다.

## 환경과 과제

- Windows, Bun 1.3.13, 공식 OpenCode 1.18.31, 공식 OmO 4.19.4, 로컬 OMM 0.1.1 소스 빌드.
- 별도 사용자 설정과 임시 프로젝트를 사용했습니다. 실제 사용자 OpenCode의 모델 설정을 교체하지 않았습니다. Git 저장소가 아닌 폴더에서 자식 프로세스의 PATH에서도 Git을 제외했습니다.
- 실제 `opencode plugin <로컬 패키지 경로> --global` 설치 후 서버를 실행했습니다. `/agent`에서 Magi와 Sisyphus를 확인하고 `/provider`에서 OpenRouter 연결을 확인했습니다.
- OpenCode의 세션 API에 `agent: magi`와 일반 한국어 목표를 보냈습니다. 목표는 고장 난 `sumPositiveIntegers` 구현을 고치고 테스트·문서를 계속 개선하는 것입니다. 기존 테스트는 문자열·음수·소수·NaN·Infinity 제외와 입력 불변성을 확인하며, 약화·삭제를 금지했습니다.
- 첫 승인 작업은 실제 OmO `task → explore`를 사용하도록 요청했습니다. 검증 성공 조건은 실제 토론·최종 투표, OmO 실행, 원본 테스트 통과, 독립 검토, 후속 회의입니다. 단순 인사나 첫 파일 읽기는 통과가 아닙니다.

## 실제 API임을 확인한 방법

인증은 OpenRouter의 `/api/v1/key`로 확인했습니다. 공개 모델 목록에서 입력·출력 가격이 0이고 도구 호출을 지원하는 `:free` 모델만 선택했습니다. OmO의 에이전트·카테고리 모델도 같은 무료 모델로 지정했습니다.

OpenCode의 요청은 로컬 계측 프록시를 거쳐 **실제 `https://openrouter.ai/api/v1/chat/completions`**로 전달했습니다. 프록시는 가짜 답변이나 투표를 생성하지 않습니다. 공급자 가격 상한을 0으로 설정하고 요청 간격을 두었으며, 실제 HTTP 상태·응답 ID·도구 호출·사용량을 기록했습니다. API 키는 프로세스 환경으로만 전달했고 설정 파일에는 환경변수 참조만 사용했습니다.

무료 모델도 공급자 가용성과 요청 제한을 받습니다. 공식 설명은 [무료 모델](https://openrouter.ai/docs/guides/routing/model-variants/free)과 [API 제한](https://openrouter.ai/docs/api_reference/limits)을 참고하세요. 이번 키에서 관측한 일일 한도는 1,000회였지만 모든 사용자에게 동일한 한도가 적용된다고 가정하면 안 됩니다.

검증 실행 자체에는 시간·무료 요청 예산을 두었습니다. 이 예산은 테스트 도구에만 적용되며, Magi의 목표·회의 반복 횟수에는 상한을 추가하지 않았습니다.

## 보완한 부분

검토자를 읽기 전용 의사결정 역할로 명시하고, 전체 개발 목표를 검토자가 직접 실행하지 않도록 지침을 추가했습니다. 제안 요청에는 같은 목표·증거를 시스템 메시지와 사용자 메시지에 중복해서 넣지 않도록 했으며, 증거 뒤에 이번 요청의 결과물인 제안 JSON을 다시 명확히 지정했습니다. 제안을 위해 필요하지 않은 재조사와 Git 이력 요구도 줄였습니다.

추가로 실제 실패 경로에서 **동일한 요청 실패를 내부 실행부와 스케줄러가 두 번 집계하는 결함**을 발견했습니다. 단 한 번의 실패에 `failureCount: 2`가 기록되고 재시도 대기가 두 배가 됐습니다. 이미 대기 중인 동일 오류를 다시 집계하지 않도록 수정했습니다. 이후 실제 재시도에서 발생하는 오류는 다시 집계합니다. 파일 기반 회귀 테스트로 두 경우를 확인했습니다.

이 변경은 모델이 맡은 역할을 구분하도록 돕는 보완과 오류 집계 수정입니다. 모델의 판단이나 투표를 코드가 대신 생성하지 않으며, 실패한 검증을 통과로 바꾸지 않습니다. 최종 회귀 검증은 **85개 테스트·355개 검증 조건**, 타입 검사와 빌드를 통과했습니다. 오류 중복 집계 수정 후 실제 모델 전체 흐름이 통과했다는 뜻은 아닙니다.

## 아직 확인해야 할 부분

1. 실제 무료 모델에서 제안 → 세 명의 첫 의견 → 상호 반박·최종 투표 → OmO 실행 → 독립 검증 → 다음 회의가 모두 이어지는지 확인해야 합니다.
2. 반복 조사와 느린 공급자 응답을 구분해 사용자 보고에 표시할 필요가 있습니다. 현재 검토 요청 실패가 일반적인 `Council proposer unavailable`로 보고될 수 있어, 세부 원인을 알려면 OpenCode/공급자 로그를 함께 확인해야 합니다. 독립 회의 세션의 읽기는 실행부 도구 집계에 포함되지 않아, 실제 읽기 요청 중에도 진행 보고의 도구 횟수가 0으로 표시됐습니다.
3. 공급자 429·요청 시간 초과·모델별 지침 준수 차이를 포함한 실제 모델별 검증이 필요합니다. 다른 유료 모델로 자동 전환해 성공을 만들지 않았습니다.
4. 짧은 실제 API 시험을 통과하더라도 무기한 가동이나 실제 연구의 품질까지 입증되지는 않습니다. 장시간 실행·재접속·재시작은 별도 검증 항목입니다.

0.1.1은 이 점검 시점에 npm에 게시되지 않았습니다. 이번 결과는 로컬 소스 빌드에 대한 것이며 공개된 0.1.0의 결과로 해석하면 안 됩니다. 원본 MAGI 컨셉 이미지는 유지했습니다.

## 2026-09-19 후속 시험

공식 Windows OpenCode **1.18.31**과 OmO **4.19.4**, Git 없는 격리 프로젝트에서 다시 실행했습니다. 비용이 0인 DeepSeek 모델 `deepseek/deepseek-v4-flash-0731:free`를 사용했고, 모델 응답이나 도구 결과를 성공 값으로 바꾸지 않았습니다.

두 시험 모두 계정의 누적 비용은 시작·종료 시 **0**이었습니다. 무료 요청 수는 병행 시험이 사용하는 계정 전체 값이므로 단일 시험의 요청 수와 같지 않을 수 있습니다. 원본 기록은 해당 PC의 임시 시험 폴더 `magi-openrouter-live-9uuyFI`, `magi-openrouter-live-pNY5eH`에 남아 있습니다. 인증 값은 저장소에 넣지 않았습니다.

이 결과를 반영해 같은 도구 입력·출력을 반복하는 경우를 정체 감지에 포함하고, 복구할 때 이미 수집한 증거를 넘기도록 보완했습니다. 인격별 기억, 부분 표결 복구, 검토 장애 복구, 사용자 제어 권한도 추가했습니다. **92개 회귀 테스트·403개 검증 조건**, 타입 검사·빌드·패키지 생성과 실제 OpenCode 1.18.29·1.18.31의 결정적 통합 시험을 통과했습니다. 정체 복구 코드의 통과를 실제 모델의 과제 완수와 혼동해서는 안 됩니다.

현재 소스의 `bun run smoke:live`는 이 실제 모델 검사를 재현하도록 추가한 도구입니다. 다른 무료 모델의 결과도 별도로 평가해야 합니다. 공개 npm 버전은 여전히 0.1.0이며, 이 변경을 포함하는 0.1.1은 아직 게시되지 않았습니다.

### 시험 환경의 결함도 분리해서 평가

후속 `nex-agi/nex-n2.5-pro:free` 비교 시험에서, 격리된 작업자의 셸이 `bun`을 찾지 못하는 사실을 확인했습니다. 상위 시험 도구의 절대 경로 검사와 모델 작업자의 명령 검색 환경이 달랐습니다. 이 조건의 실패를 모델 자체의 능력 부족으로만 해석할 수 없습니다. 기존 실패·반복 조사 기록은 남기되, 셸 환경이 정상인 재시험과 구분합니다.

시험 도구에 Git을 포함하지 않는 별도 Bun 실행 경로와 사전 검사를 추가했고, 런타임의 승인 작업에도 실제 설정된 검증 실행 파일·인자를 전달하도록 수정했습니다. 따라서 모델이 PATH에서 명령을 찾지 못해도 이미 설정된 절대 경로를 사용할 수 있습니다. 환경을 고치기 전 비교 시험은 20요청 후 중단했고 원본 행동 테스트는 실패 상태였습니다.

정확한 Windows 원인은 격리 환경에서 빠진 `PATHEXT`였습니다. Bun 파일과 PATH가 있어도 PowerShell이 `bun.exe`를 명령으로 찾지 못했습니다. 이를 복원하고 실제 OpenCode `/shell`에서 `bun --version`을 실행하는 사전 검사를 추가했습니다. 이 사전 검사는 모델 과제의 실행 실적으로 집계하지 않습니다.

### OmO 카테고리 모델 선택 문제

로드맵 수정 후 `magi-openrouter-live-o1vMNo`에서는 카테고리 위임이 요청한 무료 모델 대신 OmO 기본 모델을 선택했습니다. 시험 게이트웨이가 **실제 공급자에게 보내기 전에 차단**했습니다. 유료 호출과 비용은 발생하지 않았고, 설정 문제를 확인한 뒤 19요청에서 시험을 중단했습니다. 이를 무료 모델의 개발 능력 실패로 집계하지 않습니다.

처음에는 카테고리의 `models` 우선순위를 의심했으나, 실제 카테고리 위임 검사를 추가하자 더 근본적인 결함이 드러났습니다. **OmO 4.19.4의 공통 설정 로더는 OpenCode 전용 옵션을 대괄호까지 포함한 `"[opencode]"` 키 안에서 받습니다. 기존 OMM이 쓴 `"opencode"` 키와 최상위 `disabled_hooks`·`telemetry` 등은 전체 설정 파일을 거부하게 했습니다.** 실제 로그에 `Migration validation failed ... Unrecognized keys`가 있었습니다. 이전 시험에서 요청한 OmO 설정이 모두 적용됐다고 해석하면 안 됩니다.

프로젝트의 이전 형식은 원본을 백업한 뒤 `"[opencode]"`로 옮기도록 수정했습니다. 중첩 설정·프로필·사용자의 모델과 옵션을 보존하며, 삭제 위치에 붙어 있던 주석도 보존합니다. 명시적인 이전 카테고리 모델은 `models` 체인으로 변환하고 대체 모델·variant를 유지합니다. 이미 명시한 체인은 덮어쓰지 않습니다. 사용자 전역 설정은 직접 수정하지 않습니다.

단위 검사뿐 아니라 **실제 OmO의 `task(category: deep) → Sisyphus-Junior → read`** 검사를 추가했습니다. 지정하지 않은 기본 모델도 제공자 목록에 미끼로 노출하되 호출은 거부하므로, 카테고리 설정이 무시되면 통과할 수 없습니다. 형식 수정 전 OpenCode 1.18.29·1.18.30·1.18.31에서 이 검사가 실패하는 것을 확인했습니다. `magi-openrouter-live-pZPctk` 비교 시험도 이 형식 결함을 확인한 뒤 27요청에서 중단했습니다. 원본 테스트는 실패 상태였고 비용은 0달러였습니다.

실제 시험 도구도 에이전트·카테고리를 `models`로 지정하고 OpenCode 제공자 목록을 선택한 무료 모델 하나로 제한합니다. 예상하지 않은 모델 선택은 `denied-models.json`에 기록하고 설정 오류로 종료합니다. 실제 모델 응답을 다른 모델의 답으로 바꾸거나 재작성하지 않습니다.

형식 수정 후에는 실제 OpenCode **1.18.29·1.18.31**에서 카테고리 위임과 기존 자율 회의 흐름을 통과했습니다. 전체 회귀 **95개 테스트·418개 검증 조건**, 타입 검사·빌드·npm 패키지 생성도 통과했습니다. 실제 무료 모델 재시험은 이와 별도로 기록합니다. npm 인증 재확인은 401을 반환했고, 공개 버전은 여전히 0.1.0입니다.

추가로 OpenCode 1.18.31의 내부 구조화 메시지 조회에서 `Expected OutputFormatJsonSchema` 경고를 관찰했습니다. 공식 저장소의 [구조화 출력 메시지 조회 이슈](https://github.com/anomalyco/opencode/issues/40169)와 같은 증상입니다. OMM은 격리된 검토 요청의 직접 응답에서 결정을 받고 해당 임시 세션을 정리하므로 사용자·실행 대화에 구조화 형식을 넣지 않습니다. 경고 자체가 사라졌다고 주장하지 않으며, 향후 OpenCode 호환성 점검 항목으로 남깁니다.

### 백그라운드 완료 통지와 OMM 검토의 경쟁 상태

설정 수정판의 `magi-openrouter-live-Qk63lP` 시험에서 Nex 무료 모델의 실제 독립 의견·상호 검토·최종 투표와 OmO 위임을 확인했습니다. 그러나 부모 작업이 “탐색 결과 대기 중”이라며 잠시 쉬는 순간 OMM이 종료로 처리했고, 뒤늦은 OmO 완료 통지가 이전 부모를 깨운 뒤 두 작업이 겹쳤습니다. 이는 모델 품질과 별개인 런타임 결함입니다. 44요청에서 원인 점검을 위해 중지했으며 원본 테스트는 1개 통과·2개 실패, 계정 누적 비용은 시작·종료 모두 0달러였습니다.

백그라운드 위임에는 부모 응답과 하위 작업의 마지막 갱신 후 30초 대기, 미응답 통지 확인, 독립 검토 후 응답 ID·활동 재확인을 추가했습니다. 검토 도중 작업이 재개되면 완료를 기록하거나 다음 회의를 만들지 않고 기존 검토를 폐기합니다. 지연 응답 및 검토 중 실행 재개를 재현한 검사까지 포함해 **97개 테스트·429개 검증 조건**을 통과했습니다. 이 회귀 통과 자체가 실제 모델 과제 완수를 뜻하지는 않습니다.

사전 검사도 구분했습니다. `magi-openrouter-live-xdve8T`는 프로젝트가 아닌 상위 임시 폴더의 이전 OmO 설정 경고를 프로젝트 오류로 잘못 판단해 실제 요청 0회에서 종료했습니다. 시험 도구는 이제 해당 프로젝트의 오류만 차단하고, 실제 `/agent` 응답의 실행 담당·전문 에이전트 모델이 선택한 무료 모델인지도 확인합니다. 상위 사용자 설정은 변경하지 않았습니다.

### 웹 화면에서 확인한 범위

OpenCode 1.18.31의 실제 로컬 웹 화면에서 격리 프로젝트를 열고, 에이전트 선택 메뉴의 **Magi**와 **Sisyphus** 등 OmO 기본 에이전트를 확인했습니다. 실제 목표 세션에 최초 한국어 목표와 후속 일반 대화 스티어링, 각각의 Magi 응답이 표시됐습니다. Windows 폴더 선택에는 역슬래시 경로를 사용했습니다. 조회 확인 과정에서 새 목표나 모델 요청을 제출하지 않았습니다.

이 결과는 웹의 프로젝트·세션·에이전트 선택 표시 검증입니다. 별도 데스크톱 앱의 전체 조작, TUI의 모든 키 조작, 장시간 재접속까지 통과했다는 뜻은 아닙니다.

### 실행 종료 경합 수정 후: 실제 코드 수정과 원본 테스트 통과

`fa5d9c4` 런타임의 `magi-openrouter-live-FcQVVw`에서 `nex-agi/nex-n2.5-pro:free`를 다시 실행했습니다. 실제 제안·세 인격 토론과 최종 표결 뒤 공식 Sisyphus가 `sum.ts`를 수정하고 회귀 테스트를 추가했습니다. 작업자 테스트는 6개 통과였고, 시험 종료 후 프로젝트 밖에 보존한 **원본 행동 테스트도 3개 통과·0개 실패**였습니다. 함수 구현을 검증 도구나 사람이 대신 수정하지 않았습니다.

20분 동안 실제 요청 49회, 누적 도구 작업 52회가 발생했습니다. 계정 누적 비용은 시작·종료 모두 0달러였으며, 동시 비교 시험이 있으므로 계정의 무료 요청 증감과 이 시험의 요청 수는 다릅니다. 종료 판정은 `incomplete`, 시험 프로세스 종료 코드는 1입니다. 그 이유는 다음과 같습니다.

- 목표의 마일스톤은 미완료 상태였습니다. Magi 독립 검토와 후속 사이클까지 끝나지 않았습니다.
- 실제 OmO `task` 위임은 있었지만 `explore`는 조사 계획만 반복했습니다. 지정한 `explore → read` 조건을 충족하지 못해 `workforceVerified`는 false였습니다.
- Sisyphus와 다른 전문 에이전트가 파일 읽기·수정·검사를 수행했습니다. OmO 내부의 Oracle 검토를 Magi의 마일스톤 독립 승인으로 계산하지 않았습니다.
- 요구한 최종 증거 문서까지 완성됐다고 확인하지 않았습니다. 코드 테스트 통과를 전체 목표 완료로 확대 해석하지 않습니다.

정해 둔 시험 시간이 끝나 해당 목표와 OpenCode 프로세스를 중지했습니다. 이 시간 제한은 시험 도구에만 있으며 OMM의 지속 운영 한도가 아닙니다. 더 긴 실제 모델 실행, 전문 에이전트의 지침 준수, 독립 검토와 다음 회의의 연결은 여전히 실제 가동 검증 항목입니다.

별도로 같은 런타임의 npm 압축 패키지 `oh-my-magi-0.1.1.tgz`를 실제 OpenCode에 설치해 Git 없는 설치·기존 OmO 전환·카테고리 모델·백그라운드 결과 회수·세 사이클·중지/재개까지 통과했습니다. 증거 폴더는 `magi-smoke-TEm4ds`입니다. 이 시험은 결정적 모델 응답을 사용하므로 위의 실제 무료 모델 결과와 구분합니다. npm 레지스트리 게시 자체는 인증 401로 완료하지 못했습니다.

### 무료 공급자 비교 시험

`magi-openrouter-live-YJjjdD`에서는 [Poolside Laguna S 2.1 무료 모델](https://openrouter.ai/poolside/laguna-s-2.1:free)을 같은 과제로 시험했습니다. 공급자가 `upstream_provider_shared_pool` 원인의 HTTP 429를 반복 반환했습니다. 일부 재시도는 성공해 첫 토론·표결·기준선 조사와 보고서 저장, 실패 검증 뒤 두 번째 회의까지 진행했습니다. 이후 유효한 구조화 결정 미반환과 180초 검토 시간 초과가 발생했습니다.

44요청에서 원인 확인을 위해 중지했습니다. 원본 테스트는 1개 통과·2개 실패, 코드 구현은 초기 상태였고 계정 누적 비용은 시작·종료 모두 0달러였습니다. 전체 판정은 미통과이며, 공급자 가용성 문제와 모델의 과제 수행 능력을 같은 문제로 단정하지 않습니다. 이 시험의 목표와 서버도 종료했습니다.

최종적으로 이번 실제 시험은 **세 인격의 유효한 결정·실제 OmO 위임·실제 코드 수정·보존된 원본 테스트 통과까지의 부분 성공**을 확인했습니다. 한 번의 실행에서 지정 전문 에이전트의 실제 조사·Magi 독립 완료 승인·후속 회의까지 모두 통과한 기록과 장시간 무중단 운영 증거는 아직 없습니다. 실패나 미확인 상태를 자동 승인으로 바꾸지 않았습니다.
