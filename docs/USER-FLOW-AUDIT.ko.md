# 0.1.1 사용 흐름 재점검 — 2026-09-18

이 문서는 0.1.0에서 사용자가 실제로 겪은 설치·에이전트 노출·Git 요구 문제를 재점검한 결과입니다. 이전의 설치·명령 테스트만으로 사용자가 원한 흐름까지 검증했다고 판단한 것은 불충분했습니다.

## 사용자가 원하는 흐름

터미널에서 설치 → OpenCode 재시작 → 에이전트 목록에서 **magi 선택** → 일반 대화로 목표 입력 → Melchior·Balthasar·Casper의 첫 의견, 상호 반박, 최종 투표 → 승인 작업을 실제 OmO에 위임 → 검증·다음 회의. 목표와 회의의 반복 횟수에는 상한이 없습니다. 사용자는 같은 세션에서 평소처럼 개입합니다.

## 확인한 원인과 수정

| 문제                                | 원인                                                                                                                                      | 0.1.1 수정                                                                                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `opencode plugin omm`으로 설치 불가 | npm의 `omm`은 이 프로젝트가 아닌 HTML 변환 관련 기존 패키지입니다. OMM CLI 별칭과 npm 패키지 이름을 혼동할 수 있었습니다.                 | 공식 이름 `oh-my-magi`를 명확히 표시하고 실제 터미널 명령을 안내합니다. 타인이 소유한 `omm` 이름을 이 프로젝트의 별칭으로 게시할 수는 없습니다.                                         |
| 다른 폴더에서 에이전트가 안 보임    | 기본 설치는 프로젝트 범위입니다. 설치한 폴더와 GUI에서 연 폴더가 다르면 등록이 적용되지 않습니다.                                         | 전역 설치 `--global`을 기본 안내로 바꾸고 실제 전역 설치를 테스트합니다. doctor도 전역·상위·명시적 설정을 확인합니다.                                                                   |
| OmO 전환 중 Magi가 사라짐           | 중복 OmO를 막기 위해 초기화 예외를 던져 재시작을 요구했으나 Magi 진입점도 사라졌습니다.                                                   | 재시작이 필요한 첫 프로세스에도 선택 가능한 Magi 설정 안내 에이전트를 제공합니다. 두 번째 OmO 실행 시스템을 시작하지는 않습니다. 초기화·모델 문제도 보이는 진입점에서 설명합니다.       |
| 선택 후 대화만으로 시작되지 않음    | 런타임은 `/magi start` 또는 모델의 `magi_start` 호출을 기다렸습니다.                                                                      | 첫 일반 메시지가 Magi 에이전트에 전달되면 런타임이 목표·선택 모델을 저장하고 활성화합니다. 초기 응답은 작업 증거에서 제외하고, 이후 실제 OmO가 승인 작업을 수행합니다.                  |
| Git이 없으면 실패                   | 문맥 수집과 안전 보고에서 Git 실행 파일을 예외 처리 없이 호출했습니다. Git이 설치돼 있지만 저장소가 아닌 경우만 기존 테스트에 있었습니다. | Git을 선택 기능으로 처리하며 일반 폴더에서 시작합니다. Git 자체가 PATH에 없는 환경까지 테스트합니다. 설치·저장소 초기화를 목표의 선행 조건으로 요구하지 않도록 프롬프트도 수정했습니다. |
| 빈 폴더가 검증 명령 요구로 막힘     | 회의 시작 전에 검증 명령을 강제했습니다.                                                                                                  | 첫 승인 작업이 실제 목표에 맞는 검증 방법을 마련하도록 합니다. 검증이 없으면 완료 처리하지 않으며, 의미 있는 검증을 구축하도록 요구합니다.                                                  |
| 세 명이 독립 투표만 수행            | 같은 라운드에서는 다른 멤버의 현재 의견을 보지 못했습니다.                                                                                | 첫 의견 세 개를 공유하고 각 멤버가 다른 의견을 평가·반박한 후 최종 투표합니다. 양쪽 단계 모두 회의록에 남습니다. 반대·수정이면 같은 회의의 다음 라운드로 이어집니다.                    |
| Windows 대화 중 상태 저장 실패      | 실제 1.18.31 실행에서 상태 파일 rename이 일시적인 EPERM으로 실패했습니다.                                                                 | 파일 읽기 핸들을 닫은 뒤 상태를 원자적으로 교체하며 일시적인 Windows 파일 잠금을 재시도합니다. 기존 파일을 지워 우회하지 않습니다.                                                      |

## 검증 결과

- **84개 테스트, 350개 검증 조건, 실패 0개**, 타입 검사·빌드 통과.
- Windows의 실제 OpenCode **1.18.31** 및 공식 OmO **4.19.4**로 전역 설치·기존 OmO 전환·재시작·Magi 에이전트 선택·일반 목표 메시지·실제 task → explore → read·3회 연속 사이클·대화 개입·중지·재개·보고 생성을 통과했습니다.
- 위 통합 실행은 Git 저장소가 아닌 임시 폴더에서 수행했으며 실행 환경 PATH에서 Git을 제거했습니다. 증거 디렉터리: `C:/Users/eljja/AppData/Local/Temp/magi-smoke-PrXwAi/`.
- 배포용 0.1.1 tarball을 개발 의존성 없이 새 npm 소비자 폴더에 설치한 뒤 OpenCode **1.18.29**에서도 같은 Git 없는 실행·기존 OmO 전환·일반 대화 시작·3회 사이클을 통과했습니다. 증거: `C:/Users/eljja/AppData/Local/Temp/magi-smoke-OjK6tN/`. 패키지 SHA-1: `bbf43f5ce2ce03961bf2176898cc2ef5ffe571bb`.
- OpenCode 1.18.31 웹 화면에서도 전역 설치된 **Magi가 에이전트 선택 목록에 표시되고 실제 선택되는 것**을 확인했습니다. 별도 일반 폴더의 화면에는 `Git 없음`이 표시됐습니다. 전체 데스크톱·TUI 조작과 재접속까지 검증한 것은 아닙니다.
- 첫 원격 CI에서 Linux·macOS의 최소/최신 검증은 통과했고, Windows 최신 버전은 초기 `/agent` 로딩 중 120초 제한을 넘겼습니다. 초기 플러그인 로딩만 300초로 분리하고 요청별 오류·서버 로그·CI 진단 파일을 보존하도록 보완했습니다. 작업/모델 요청 제한은 기존대로 유지합니다. [재검증 실행](https://github.com/eljja/Magi/actions/runs/35353297752)에서 **Windows·macOS·Linux × 최소/최신 OpenCode의 6개 조합과 코어 검증이 모두 통과**했습니다. 테스트의 초기 로딩 대기 조정이며, Magi의 회의·목표 반복 횟수를 제한한 변경은 아닙니다.

**모델 응답은 테스트용 가짜 서버를 사용했습니다.** 실제 OpenCode·OmO·도구·파일·스케줄러를 검증한 것이며, 실제 LLM의 장기 연구 품질까지 확인한 것은 아닙니다.

## 설치와 남은 조건

0.1.1 패키지 제작과 설치 검증은 완료했습니다. 현재 npm 인증이 만료(E401)되어 공개 게시에는 사용자 재로그인이 필요합니다. 아직 배포된 0.1.0을 이번 수정판으로 혼동하지 마세요.

0.1.1 공개 후 운영체제 터미널에서 실행합니다.

```sh
opencode plugin oh-my-magi@0.1.1 --global
```

OpenCode를 재시작하고 `magi`를 선택해 목표를 말합니다. 기존 OmO 설정 전환 안내가 있으면 한 번 더 재시작합니다. 로컬에서 검증한 OpenCode는 1.18.31이며 최소 지원 버전은 1.18.29입니다. 0.1.0에는 이 문서의 수정이 들어 있지 않습니다.

OpenCode 모델 연결은 필요합니다. 모델·권한 설정 제약은 유지됩니다. Git은 이 플러그인의 일반 실행 요건이 아니지만 사용자가 Git 커밋·브랜치 작업 자체를 목표로 요청했다면 그 작업에는 Git이 필요합니다. 시작한 목표는 같은 폴더에서 유지되며 다른 목표로 조용히 교체되지 않습니다. 중지한 목표는 명시적으로 재개해야 합니다.
