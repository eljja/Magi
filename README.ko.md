# Oh-My-Magi

**하나의 목표를 지속적으로 발전시키는 Magi 의회와 실제 OmO 실행 시스템.**

**최초 설치·CLI·GUI 실측:** [2026-09-20 전체 평가](docs/END-TO-END-AUDIT.ko.md)에 공개 패키지 설치, 실제 무료 모델, 화면 조작 결과와 미통과 항목을 구분했습니다. 실제 코드 수정과 원본 검사 통과 후 다음 회의까지 이어졌지만, 중복 결정 호출이 재발해 **무인 연속 운전 검증은 미통과**입니다. Windows 데스크톱 직접 사용 검증도 남아 있습니다.

**지속 운영 개선:** 기본 모드에서 별도의 완료 표결을 없앴습니다. 진행 내용과 검사 결과를 다음 회의로 넘기며 같은 목표를 계속 개선합니다. **약 4시간의 실제 가동마다, 또는 세 인격이 이미 발생한 큰 변화에 합의할 때** 보고합니다. 보고 때문에 작업을 중지하지 않습니다. [현재 운영 방식과 검증 범위](docs/CONTINUOUS-OPERATION.ko.md)를 확인하세요. 이전 무료 모델 시험에서는 실제 코드·테스트·문서 수정과 원본 테스트 통과를 확인했지만 새 방식의 장기 실제 모델 운전까지 입증한 것은 아닙니다. [과거 실제 모델 기록](docs/REAL-MODEL-AUDIT.ko.md)도 보존합니다.

Oh-My-Magi(OMM)는 OpenCode에서 [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent)(OmO) 위에 동작하는 연구·개발 상위 시스템입니다. 공식 `oh-my-opencode@4.19.4`를 의존성으로 설치하고 실제 서버 플러그인을 초기화합니다. OmO의 에이전트·도구·전문가 위임·백그라운드 작업 관리 기능을 그대로 사용합니다.

Magi는 하나의 목표를 저장하고 다음 작업을 제안합니다. Melchior·Balthasar·Casper가 각자 첫 의견을 낸 뒤 서로의 의견을 읽고 반박·수정하며 최종 투표합니다. 승인한 작업은 실제 OmO가 실행합니다. 의미 있는 진전·실험 결과·문제가 생기고 실행이 자연스럽게 대기 상태가 되면 검사 결과를 다음 계획 회의에 반영합니다. **반복 횟수 제한은 없으며 목표 완료 표결을 기다리지 않습니다.**

세 인격은 각각 분리된 세션과 자신의 판단 이력을 사용합니다. 같은 모델을 쓰거나 인격마다 다른 모델을 지정할 수 있습니다. 세 명 모두 유효한 최종 투표를 제출해야 표결 정책을 적용하며, 일부 장애가 나면 이미 받은 의견을 보존하고 같은 회의를 이어갑니다. 승인된 작업은 별도의 공식 OmO 하위 세션이 실행하므로, 사용자 대화의 접수·설명 지시가 작업 실행을 방해하지 않습니다.

**진행을 축적하고 다음 방향을 결정합니다.** `magi_submit`은 선택적인 진행 기록 도구입니다. 호출하지 않아도 실제 응답과 도구 결과로 다음 회의를 이어갑니다. 테스트 실패는 다음 수정의 근거로 남기고, 통과를 목표 전체의 완료로 바꾸지 않습니다. 기존 `selfImprovement.mode: "complete"`를 명시한 경우에만 완료 검토 방식을 유지합니다.

새 목표의 기본 로드맵은 사용자가 요청한 결과물 자체를 기준으로 삼습니다. 조사·구현·실험 순서는 의회가 정하고, 조사만 반복하거나 테스트를 약화해서 완료 처리하지 않습니다. 기존에 저장한 로드맵은 보존합니다. 같은 도구 결과를 반복하는 실행은 정체 시간에 따라 복구하며 목표·회의 횟수에는 상한이 없습니다.

## 설치

**0.1.1이 npm에 공개됐습니다.** `latest` 태그와 직접 내려받은 배포 파일의 해시를 확인했습니다. 아래 명령으로 설치할 수 있으며, 기존 0.1.0 사용자는 갱신해야 이번 개선이 적용됩니다.

운영체제 터미널에서 전역 설치한 뒤 OpenCode를 재시작합니다. 다른 폴더를 열어도 Magi를 선택할 수 있습니다. OpenCode 안의 AI 대화창에 설치 명령을 보내는 방식이 아닙니다.

```sh
opencode plugin oh-my-magi@0.1.1 --global
```

정식 npm 이름은 **oh-my-magi**입니다. **omm은 약칭이며, `opencode plugin omm`은 관계없는 다른 npm 패키지를 가리킵니다.** `--global`을 생략하면 현재 프로젝트에만 설치됩니다.

OMM 하나만 등록하면 고정 버전의 OmO를 함께 불러옵니다. 기존에 OmO가 설치돼 있으면 인식 가능한 등록을 백업하고 OMM으로 전환하며, 모델·에이전트 설정은 보존합니다. 시작 중 전환 안내가 나오면 **OpenCode를 한 번 재시작**하면 됩니다. 이미 로드된 OmO와 이중으로 실행되는 것을 방지하기 위한 과정입니다.

현재 소스는 Bun 1.3.13 이상과 OpenCode 1.18.29 이상을 지원 대상으로 하며, 최신 SDK·호환성 대상은 1.18.31입니다.

```sh
git clone --branch omm https://github.com/eljja/Magi.git
cd Magi
bun install --ignore-scripts
cd packages/oh-my-magi
bun run build
bun bin/cli.ts install --local --project /프로젝트/절대경로
```

빌드 후 대상 프로젝트에서 `opencode plugin /Magi/packages/oh-my-magi/절대경로`로 등록할 수도 있습니다. 기존 설치에서 전환한다면 위 OMM 설치 도구가 인식 가능한 구형 등록을 백업·정리합니다.

Git이 없는 PC에서는 [omm 소스 ZIP](https://github.com/eljja/Magi/archive/refs/heads/omm.zip)을 내려받아 압축을 풀고, 그 폴더에서 `bun install --ignore-scripts`부터 진행하면 됩니다. 소스 설치에도 Git 설치가 필수는 아닙니다.

OpenCode에 모델을 연결하고 **에이전트 목록에서 `magi`를 선택한 다음 목표를 말하면 자동 시작합니다.** Git 설치나 Git 저장소는 필수 조건이 아닙니다. 검증 명령이 없으면 첫 승인 작업에서 마련하며, 검증이 없는데 완료했다고 처리하지 않습니다.

```text
이 연구 파이프라인의 재현성과 정확도를 지속적으로 개선해줘
/magi status
새로운 실험보다 기존 결과의 재현성을 우선해줘.
왜 이 방식을 선택했어? 설명만 해줘.
/magi stop
/magi resume
```

OpenCode에 연결된 로컬 LLM도 사용할 수 있습니다. 모델 인증은 OpenCode가 관리하며, OmO의 에이전트별 모델 제약은 유지합니다. 처음 보낸 목표를 런타임이 직접 저장하므로 별도 시작 명령이 필요 없습니다. 별도 회의 모델 설정이 없으면 선택한 모델을 회의·검토에도 사용합니다. 이후 대화는 같은 목표의 지시로 누적되며 중지한 목표는 명시적으로 재개할 때까지 유지됩니다.

## 보고와 사용자 개입

4시간/주요 변화 보고는 원래 OpenCode 대화와 `.magi/LATEST-REPORT.md`에 남습니다. 모델을 추가 호출하지 않고 자동 보고임을 표시한 기록을 저장합니다. 일시 중지와 서버가 꺼진 시간은 가동 시간에 넣지 않습니다. 보고 전송이 실패해도 개발은 계속합니다.

인격별 독립 의견과 최종 표결 이유를 도착한 순서대로 표시합니다. 서버 저장과 페이지 새로고침 주기를 합쳐 반영까지 보통 15~30초가 걸릴 수 있으며, TUI 패널은 2초마다 읽습니다. 명령 팔레트의 **Open Magi Live Monitor** 또는 `bunx oh-my-magi monitor --project <프로젝트>`로 페이지를 엽니다. 소스 설치에서는 패키지 폴더에서 `bun bin/cli.ts monitor --project <프로젝트>`를 사용하세요.

프로젝트의 **`.magi/index.html`**을 브라우저에서 열면 목표, 실행 상태, 의회 표결, 최근 결정, 도구 활동, 대기 중인 사용자 지시를 볼 수 있습니다. 페이지는 15초마다 갱신됩니다. 목표를 실행 중인 OpenCode 세션에서 Sisyphus에게 말하듯 평소처럼 대화하면 됩니다. 별도 스티어링 명령은 필요하지 않습니다.

| 파일                            | 내용                                                                |
| ------------------------------- | ------------------------------------------------------------------- |
| `.magi/COUNCIL.md`              | 제안·토론·승인·거절·수정 요구·실행 결과·사용자 개입을 누적한 회의록 |
| `.magi/members/*.md`            | 인격별 최종 판단 이력. 이후 같은 인격이 자신의 과거 의견을 참고     |
| `.magi/STATUS.md`               | 최신 진행 보고                                                      |
| `.magi/reports/YYYY-MM-DD.md`   | 매분 누적하는 상세 상태 기록 — 대화 알림 아님                          |
| `.magi/LATEST-REPORT.md`        | 4시간 또는 세 인격 합의에 따른 최근 사용자 보고                         |
| `.magi/reports/msg_*.md`        | 사용자 진행 보고의 전체 이력                                         |
| `.magi/events/YYYY-MM-DD.jsonl` | 진행 중인 표결과 오류까지 남기는 이벤트 기록                        |
| `.magi/ROADMAP.md`              | 마일스톤과 검증된 진행 상황                                         |
| `.magi/runtime/`                | 목표·소유 세션·사용자 지시·재개 상태                                |

Melchior는 구조와 과학적 타당성, Balthasar는 위험과 안전, Casper는 실용성과 사용자 의도를 평가합니다. 의회의 실제 LLM 판단과 자동 수집한 도구 활동은 구분해서 표시합니다. 하위 에이전트의 도구 활동도 수집하며, 도구가 반환됐다는 사실만으로 성공했다고 기록하지 않습니다.

실행 중인 목표 세션의 일반 대화는 회의록에 기록되고 다음 회의에 전달됩니다. 질문에는 대화로 답하며, 질문을 작업 변경 승인으로 간주하거나 그 답변을 마일스톤 완료 증거로 사용하지 않습니다. 지시는 승인된 다음 작업에 반영될 때까지 보존합니다. 다른 세션의 대화나 중지 상태의 대화는 목표에 개입하거나 자동 실행을 재개하지 않습니다. `/magi steer`는 기존 사용자를 위한 선택 사항으로 남아 있습니다. 회의 중에도 보고는 별도 타이머로 갱신하며, 중지 후 같은 목표로 재개할 수 있습니다.

회의 라운드에도 횟수 제한을 두지 않습니다. 승인되지 않은 회의는 반론을 저장하고 다음 라운드에서 초안을 수정·재심의합니다. `USER-GUIDANCE.md`에는 대화 원문을, `MEMORY.md`에는 요약 기억을 유지하며, 이후 회의와 컨텍스트 압축 때 기존 회의록과 함께 다시 읽습니다. 정체된 실행은 감시기가 복구하며, 일시적 장애에는 대기 간격을 늘려 재시도합니다.

인격별 요청·응답·오류 상태는 실행 도구 횟수와 별도로 표시합니다. 같은 도구 결과만 반복하는 것을 진전으로 세지 않으며, 정체 복구 시 이미 수집한 증거를 다음 시도에 전달합니다. 독립 검토가 실패해도 실행 증거를 보존하며, 재검토할 때 현재 파일에 대한 검증 명령을 다시 실행합니다. 작업자는 사용자 대신 목표를 중지하거나 스티어링할 수 없습니다.

Windows에서 OpenCode 자체가 기존 런타임 폴더의 읽기 전용 속성 때문에 `EEXIST`로 시작하지 못하면 `bunx oh-my-magi doctor --repair-windows --project <프로젝트>`로 점검한 뒤 재시작하세요. 파일이나 접근 권한 목록은 변경하지 않습니다. 자세한 운영·버전 갱신 절차는 [패키지 문서](packages/oh-my-magi/README.md)를 참고하세요.

## OmO와 Magi의 역할

**OmO가 실행하고 Magi가 목표·회의·검증·다음 작업을 관리합니다.** 초기 작업도 실제 OmO 실행 에이전트에 전달합니다. 에이전트 이름만 설정에 있는지 확인하는 대신 런타임에서 실행 에이전트를 검증하며, 없으면 기본 에이전트로 조용히 대체하지 않습니다.

두 시스템이 서로 다음 작업을 시작하는 충돌을 막기 위해 `.omo/omo.jsonc`에서 OmO의 `todo-continuation-enforcer`, `goal`, `atlas` 스케줄링 훅을 비활성화합니다. 기존 설정은 보존·백업합니다. Atlas를 포함한 OmO 에이전트와 도구는 유지하며, 독립 반복 제어는 Magi가 담당합니다.

무인 실행에는 OpenCode 서버가 계속 살아 있어야 합니다. 서버를 재시작하고 프로젝트를 불러오면 저장된 목표로 복구합니다. 플러그인 자체가 운영체제 서비스를 설치하거나 꺼진 컴퓨터에서 실행되지는 않습니다.

## 검증 범위

Windows의 실제 OpenCode **1.18.29·1.18.31**과 공식 OmO **4.19.4**에서 Git 없는 일반 폴더, 전역 설치, 기존 OmO 전환·재시작, Magi 선택 후 일반 목표 입력, `task → explore → read` 위임, 3회 연속 사이클, 대화 개입, 중지·재개, 보고 생성을 테스트용 모델 서버로 검증했습니다. 회귀 검사에는 중간 투표 복구·실행 세션 분리·검토 장애·제어 권한·반복 도구 정체도 포함합니다. [최신 설계·검증 문서](docs/AUTONOMY-DESIGN.ko.md)를 확인하세요.

실제 제공자 시험은 `bun run smoke:live`로 재현할 수 있습니다. 현재 가격이 0인 OpenRouter 무료 모델만 허용하며, 원본 행동 테스트를 작업 폴더 밖에 보존해 최종 결과를 별도로 확인합니다. 자세한 [시험 절차](docs/AUTONOMY-DESIGN.ko.md#검증과-재현)를 참고하세요.

CLI·데스크톱·웹은 같은 서버 기능을 사용합니다. 터미널 패널은 TUI 전용이며, 모니터 페이지는 별도로 여는 로컬 문서입니다. **실제 모델 장기 실행과 데스크톱·TUI 전체 조작 및 재접속 검증은 아직 남아 있습니다.** 게시한 구현의 Linux·macOS·Windows 최소/최신 OpenCode [6개 CI 조합과 코어 검증이 모두 통과했습니다](https://github.com/eljja/Magi/actions/runs/35451257603). [한글 사용 흐름 점검](docs/USER-FLOW-AUDIT.ko.md)을 확인하세요.

OMM 자체 코드는 MIT이며, **OmO 의존성은 SUL-1.0**입니다. [라이선스 고지](packages/oh-my-magi/THIRD-PARTY-NOTICES.md)를 확인하세요. 이 저장소는 OmO 공식 제품이 아닙니다.

**npm 배포 상태:** [oh-my-magi 0.1.1](https://www.npmjs.com/package/oh-my-magi/v/0.1.1)이 `latest`로 공개됐습니다. 위 지속 운영·보고 개선을 포함하며, 내려받은 파일이 검증한 배포 파일과 일치합니다. [게시 기록](docs/RELEASE-AUDIT.md#publication-011)을 확인하세요.
