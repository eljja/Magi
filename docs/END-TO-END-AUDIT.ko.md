# 최초 설치부터 CLI·GUI 실행까지 — 2026-09-20

현재 공개 npm 버전은 **0.1.1**입니다. 아래에서는 공개 패키지의 설치 결과와 그 뒤 발견한 문제를 고친 로컬 소스의 실행 결과를 구분합니다. 실행 중이라는 사실이나 모델의 설명만으로 자율 개발 성공을 판정하지 않습니다.

## 설치와 실행 환경

| 항목 | 판정 | 실제 확인한 범위 |
| --- | --- | --- |
| 공개 npm 배포 | 통과 | `latest=0.1.1`, 레지스트리에서 내려받은 파일과 검토한 압축 파일의 해시 일치 |
| 빈 환경에서 첫 설치 | 통과 | OpenCode 1.18.31의 `plugin oh-my-magi@0.1.1 --global`, 별도 홈·설정·캐시 사용 |
| OmO가 없는 환경 | 통과 | 공식 `oh-my-opencode@4.19.4` 의존성을 자동으로 설치하고 실제 플러그인 로드 |
| OmO가 이미 있는 환경 | 통과 | 기존 등록 백업·전환 후 재시작, 실제 OmO 에이전트와 `task` 사용 |
| Git 없는 일반 폴더 | 통과 | Git이 없는 PATH에서 설치·회의·작업·보고 실행 |
| CLI/TUI | 부분 통과 | 실제 `opencode attach`, Magi 대화, 명령 팔레트의 상태 조회, 자동 보고 표시 확인. 모든 단축키·창 크기를 검증한 것은 아님 |
| OpenCode 웹 GUI | 통과한 흐름 명시 | Magi 선택, 일반 한국어 목표 입력, 실제 모델 응답, 상태·투표 조회, 자연어 중지·재개, 자동 보고 표시 |
| Windows 데스크톱 앱 | 미통과 | 공식 서명된 1.18.31 설치 파일의 압축 해제본을 격리 프로필로 실행했으나 로고 화면에 머묾. 플러그인 설치 전의 호스트 초기 화면 문제이며 원인은 확정하지 않음 |
| 로컬 감시 HTML 화면 | 이번 검사 미실시 | 기존 접근 차단을 우회하지 않음. 파일 생성·기록 검증과 직접 화면 검증을 구분 |
| 실제 모델 4시간 이상 연속 운전 | 미통과 | 단기 GUI 검사와 재현용 모델 검사가 장시간 운전을 증명하지 않음 |

설치 명령은 OpenCode 대화창이 아니라 운영체제 터미널에서 실행합니다.

```sh
opencode plugin oh-my-magi@0.1.1 --global
```

`omm`은 약칭입니다. `opencode plugin omm`은 다른 npm 패키지를 가리킵니다. 설치 후 OpenCode를 다시 열고 **Magi**를 선택한 다음 목표를 평소 대화처럼 입력합니다. 모델 제공자 연결은 별도로 필요하며 플러그인이 사용자의 API 계정을 만들어 주지는 않습니다.

## 실제 모델에서 발견하고 수정한 문제

1. **의회가 결정 도구를 한 응답에서 여러 번 호출:** 무료 모델이 중복 `StructuredOutput`을 보내 OpenCode의 반복 호출 보호에 차단됐습니다. 검토 세션에 단일 결정 호출을 명시하고 공급자별 병렬 도구 호출 옵션을 적용했습니다. OpenRouter 전용 SDK에서는 `parallel_tool_calls: false`가 실제 HTTP 요청에 들어가는 것을 확인했습니다. 실행 에이전트의 병렬 작업과 기본 권한 보호는 유지합니다.
2. **같은 제안자가 거절된 안건을 반복:** 거절된 회의의 다음 라운드에서는 제안자를 순환합니다. 최근 세 라운드를 프롬프트에 넣고 전체 회의 기록은 보존합니다. 회의 횟수 제한을 추가한 것이 아닙니다.
3. **Windows 경로 철자 논쟁 때문에 조사·수정조차 승인되지 않음:** 의회에는 검사 이름을 제공하고 실행자에게는 실제 실행 파일·인자 배열을 전달합니다. 기계 검사는 런타임이 그대로 시행하며 경로를 모델이 다시 베껴 쓰는 것을 승인 요건으로 삼지 않습니다.
4. **진행 보고에 제출 JSON이 노출:** 제출 요약·산출물·미해결 사항을 읽을 수 있는 텍스트로 전달합니다. OpenCode 사용자 메시지로 표시되는 자동 보고의 Markdown 제목 기호는 아직 그대로 보일 수 있습니다.
5. **자연어 재개 때 저장 목표를 다른 문장으로 바꿈:** 실제 모델이 `magi_start`에 목표를 요약해서 넣었다가 거절된 뒤 원문으로 재시도했습니다. 이제 인자 없는 `magi_resume`이 저장한 목표를 그대로 재개하며 OmO의 취소 상태도 함께 복구합니다. 사용자가 별도 명령을 외울 필요는 없습니다. 작업자는 과거 중지 요청을 다시 실행하지 않도록 안내합니다.

위 수정은 공개된 0.1.1 파일과 구분해야 합니다. 현재 소스의 검사 결과는 **112개 테스트 통과, 538개 assertion, 타입 검사·빌드 통과**입니다. `magi-smoke-CFWpcT`에서 새 재개 도구를 실제 OpenCode를 통해 호출하고, 공식 OmO의 취소 상태 복구 후 실제 `task`가 다시 실행되는 것까지 통과했습니다.

## 증거와 판정 원칙

로컬 시험 자료는 `.tmp/omm-integration/`에 보존합니다. 인증 값은 기록하지 않습니다.

- `magi-smoke-gQaCle`: 공개 npm 0.1.1의 빈 환경 설치, 실제 OmO 위임, Git 없는 실행 검사. 모델 응답은 재현용입니다.
- `magi-smoke-DUmgl2`: 수정 소스의 설치·기존 OmO 전환·3회 이상 연속 진행·보고·명령 중지/재개 검사. 모델 응답은 재현용입니다.
- `magi-smoke-CFWpcT`: 최종 소스의 별도 통합 검사. 재개 도구의 실제 호출·완료와 재개 후 OmO 작업, 연속 회의·보고를 확인했습니다. 모델 응답은 재현용입니다.
- `magi-openrouter-live-cNI2rs`: 실제 무료 모델의 이전 운전. 첫 회의가 반복 거절됐고 원본 행동 검사가 실패했습니다. GUI 중지 검사를 위해 의도적으로 멈췄으며 장시간 성공으로 기록하지 않습니다.
- `magi-openrouter-live-irMYjo`: GUI에서 Magi를 직접 선택하고 한국어 목표를 입력해 자동 시작, 실제 OmO 위임 확인. OpenRouter 옵션 전달 문제를 발견하고 수정하기 위해 종료했습니다.
- `magi-openrouter-live-ZeSvNG`: 수정한 OpenRouter 옵션을 실제 HTTP 요청에서 확인한 후 GUI·CLI 공동 검증. **약 12.3분, 시험 요청 80회, 2번째 회의, 자동 보고 3회**, 실제 OmO 위임을 확인했습니다. 문서·추가 테스트가 만들어졌지만 `sum.ts`는 아직 수정되지 않아 보호한 원본 검사 3개 중 2개가 실패했습니다. 시작·종료 계정 사용액은 모두 0입니다. 시험기에 설정한 80요청 한도에 도달해 종료한 것이며, 종료 시 공급자 무료 잔여량은 727회였습니다. 이 기록의 `free-request-allowance-reached`는 공급자 잔여량 소진을 뜻하지 않습니다. 시험기도 이후 시험 예산과 공급자 한도 판정을 분리했습니다.

마지막 GUI 검사에서는 **시험 프로젝트만 보고 간격을 2분으로 변경**했습니다. 자동 보고가 원래 대화에 나타난 뒤에도 루프와 실행이 유지되는지를 확인하기 위한 검사이며, 기본 4시간 보고의 실시간 내구성 시험으로 계산하지 않습니다. 제품의 반복 횟수 제한은 계속 없습니다.

최종 실제 개발 판정에는 시험 폴더 밖에 보존한 원본 행동 검사, 실제 OmO 도구 실행, 다음 회의로 이어진 진행 기록을 함께 사용합니다. 모델의 “완료했습니다” 문장, 도구 호출 횟수 또는 초록색 HTTP 응답만으로 통과시키지 않습니다.

## 남은 사용자 경험 문제

- 데스크톱 전용 앱은 정상 대화 화면에 도달하지 못해 Magi 설치·선택·재접속을 통과로 표시할 수 없습니다. 일반 설치 마법사 자체도 이번 압축 해제 실행으로 대체 검증되지 않습니다.
- 웹 GUI에는 TUI 전용 Magi 패널이 없습니다. 현재 대화에서 실제 투표를 조회하거나 생성된 회의록을 볼 수 있지만, 웹 내부에 항상 표시되는 3인 투표 패널은 별도 구현 대상입니다.
- 폴더 선택기의 중간 경로를 열 때 `.magi`·`.omo` 초기화 파일이 생기는 부작용을 줄일 필요가 있습니다.
- 무료 모델의 잘못된 경로, 불필요한 재조사·위임, 공급자 속도 제한은 실제 생산성을 떨어뜨릴 수 있습니다. 회복 가능한 루프와 유용한 개발 성과를 따로 측정해야 합니다.
