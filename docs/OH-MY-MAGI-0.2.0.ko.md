# oh-my-magi 0.2.x 통합 배포 기록

## 0.2.1 Windows 경로 수정

공개 Windows CI에서 실제 결함을 발견했습니다. Bun 1.3.13의 `realpathSync`는 8.3 짧은 경로를 유지하고 비동기 `realpath`는 긴 경로를 반환하여 같은 프로젝트를 외부 폴더로 잘못 판정했습니다. 임시 폴더를 `GetShortPathName`으로 바꾸어 이 차이를 재현했습니다.

0.2.1은 검증 시 프로젝트 기준 경로와 실행 경로를 같은 API로 정규화합니다. 실제 짧은 경로에서 검증 성공과 다음 회차 진행을 확인하는 회귀 시험, 프로젝트 밖 경로를 계속 거부하는 시험을 추가했습니다. 기존 0.2.0 아카이브는 덮어쓰지 않습니다.

로컬 Windows에서 `bun run verify`가 종료 코드 0으로 완료됐습니다. 테스트 **66개, assertion 288개**, 타입 검사, 패키지 설치·의존성 감사와 OpenCode **1.18.29 / 1.18.33**의 실제 native 실행 검사가 통과했습니다. 이 결과의 아카이브 SHA-256은 `7a84fd90497020aa8940d541201deadaa638adabf706ca438bf34fec903d9701`이며, 전체 실행 기록은 `2026-09-30T13-34-29-400Z-qualification-42596b89`입니다.

다만 [첫 원격 CI](https://github.com/eljja/Magi/actions/runs/36722675178)는 Linux·macOS 및 core 검사를 통과했지만, Windows native 검사의 검증 명령 뒤 프로세스 정리에서 실패했습니다. Windows 정리 프로세스의 표준 입출력을 명시하고 종료 코드·신호·소요 시간·정리 단계 진단을 추가했습니다. [후속 CI](https://github.com/eljja/Magi/actions/runs/36725092822)의 최신 OpenCode Windows native 검사는 실제 작업·보고·자동 복구·중지까지 통과했습니다. 같은 실행의 최소 버전 Windows 검사는 테스트 단계의 기본 5초 제한 때문에 실패했습니다. CI도 패키지의 `bun run test`를 사용해 로컬과 같은 30초 제한을 적용하고 다시 검사합니다.

0.2.1의 첫 npm 게시 요청은 추가 인증 처리 중 404로 종료됐으며 게시 수락을 확인하지 못했습니다. 2026-09-30 14:01 UTC에 **0.2.0**의 공개 조회와 다운로드를 확인했고, 검증한 아카이브와 SHA-256이 일치했습니다. **0.2.1 공개 설치가 완료됐다는 뜻은 아닙니다.** 수정본의 새 아카이브와 전체 결과는 완료 후 아래에 추가합니다.

추가 [재검사](https://github.com/eljja/Magi/actions/runs/36726843500)에서는 Windows 정리 오류가 재현됐습니다. 진단 결과는 `cleanup started` 뒤 `Get-CimInstance Win32_Process`에서 20초 제한을 초과한 종료 코드 143/SIGTERM이었습니다. 입출력 명시만으로 해결됐다고 판단하지 않고 WMI/CIM 의존성을 제거합니다. Windows Toolhelp 스냅샷으로 부모 관계를 조회하고, 프로세스 핸들에서 생성 시각을 확인한 뒤 같은 핸들로 종료합니다. 기존 부모·생성 시각·LSP named pipe 소유권 검사는 유지합니다. 종료된 부모의 자식 정리, 무관한 프로세스 보존, 잘못된 생성 시각 거부와 native 호스트의 격리 환경을 시험합니다. 이 수정도 새 아카이브로 검증합니다.

아래는 0.2.0 후보에 대한 실제 이력이며 0.2.1의 시험 결과로 합산하지 않습니다.

## 0.2.0 통합 후보 이력

2026-09-30. 사용자가 최신 구현을 기존 npm 이름 **oh-my-magi**로 통합해 게시하도록 명시했습니다. 검증과 본인 인증을 마쳤고 npm이 게시 요청을 수락했습니다. 이후 14:01 UTC에 공개 다운로드와 아카이브 일치를 확인했습니다. 후속 Windows CI에서 발견한 문제는 위의 0.2.1 수정 이력으로 별도 기록합니다.

## 배포 대상

- 최신 지속 운영 소스: `packages/oh-my-openmagi`, npm 이름 `oh-my-magi`, 버전 `0.2.0`.
- 이전 `packages/oh-my-magi`는 `oh-my-magi-legacy`라는 비공개 workspace로 보존합니다. 두 패키지를 동시에 게시하지 않습니다.
- OmO 4.19.4를 원본 의존성으로 사용합니다. 공개 CLI는 `oh-my-magi`이며 `omm`과 이전 개발명은 CLI 별칭입니다.
- 현재 패키지의 자기 등록 허용, OmO/Magi 중복 등록 검사, 모든 CLI 별칭의 사용자 제어 보호를 이름 통합에 맞게 수정했습니다.
- 기존 OpenMagi 데이터·환경변수·설정 경로를 유지합니다. 0.1.x의 목표 상태는 자동 승계하지 않으며, 이전 호스트를 중지하고 설치 전환 후 목표를 다시 입력합니다. 회의·보고 문서는 백업합니다.

세 버전 모두 실제 OpenCode 실행 파일과 원본 OmO를 사용하며, 모델 응답은 결정적인 로컬 fixture입니다. Magi primary/숨김 council 3개 등록, 원래 OmO 에이전트 정의 보존, 세 표 의결과 잘못된 표 재시도, 실제 `task → specialist → read/LSP`, 검증 후 다음 회의, 정기 보고, native 프로세스 강제 종료 후 자동 복구와 명시적 중지 유지가 검사 대상입니다. 보고 시험은 12초 간격으로 수행합니다. 이번 게시 검증에서 실제 GUI 화면을 새로 조작하거나 실제 외부 LLM 장기 시험을 수행했다고 주장하지 않습니다.

OmO는 검증한 **4.19.4**로 고정합니다. 의존성 감사에서 기존 `@babel/core` Low 권고 `GHSA-4x5r-pxfx-6jf8` 1건을 확인했으며 문서화된 미패치 예외입니다. 새 Moderate/High/Critical 권고는 해당 검사에서 확인되지 않았습니다.

게시 후보 SHA-256: `c16f531fb12bdfad9a5768ce721547e7550804271136e4168b492377bb84312f`.

CI와 게시 workflow도 최신 구현으로 연결했습니다. 최소 버전과 실행 시점의 npm 최신 OpenCode를 검사하며, 비공개 runtime 디렉터리 대신 정리된 결과 파일만 보관합니다.

검증 증거는 `packages/oh-my-openmagi/artifacts/runs/`에 보존합니다. 타입·테스트·pack·audit 명령은 종료 코드 0이며, 각 native 시험은 정리 후 `passed` 결과를 기록했습니다. 이를 감싼 `verify` 프로세스는 마지막 native 자식이 종료된 뒤 출력 수집 대기에 남아 소유권을 확인하고 종료했습니다. 따라서 `bun run verify` 전체 명령이 정상 종료했다고 기록하지 않으며, 게시 전 검사는 같은 tarball과 소스 해시에 연결된 개별 검사 결과를 모두 다시 확인합니다.

- 타입·테스트·pack·audit 실행: `2026-09-30T13-04-23-475Z-qualification-582ddd99`.
- 1.18.29: `2026-09-30T13-05-40-423Z-native-smoke-fc92c32c`.
- 1.18.31: `2026-09-30T13-10-19-223Z-native-smoke-382f8321`.
- 1.18.33: `2026-09-30T13-08-20-616Z-native-smoke-a7bf0290`.

Git의 저장소 전체 pre-push 타입 검사는 Windows가 `turbo.exe` 실행을 EPERM으로 거부해 시작하지 못했습니다. 위 패키지 검사를 대신 근거로 삼아 이번 push에서만 Husky 실행을 생략하며 훅 설정 자체는 변경하지 않습니다. 저장소 전체 타입 검사나 원격 CI가 통과했다고 주장하지 않습니다.

**이번 배포본은 6시간 구동 평가를 진행하지 않았습니다. 다른 프로젝트의 장기 평가 기록은 이번 배포의 통과 증거나 게시 조건으로 사용하지 않습니다.** 이번 검사에서 직접 확인한 결과만 아래에 기록합니다.

## 게시·설치

게시 완료 후 사용할 최초 설치 명령:

```sh
opencode plugin oh-my-magi@0.2.0 --global
```

기존 OmO/Magi 환경은 이전 목표와 호스트를 중지하고 다음 명령으로 등록을 백업·전환합니다.

```sh
bun install --global oh-my-magi@0.2.0
oh-my-magi install --global --project /대상/프로젝트
```

프로젝트에도 별도 등록이 있으면 `--global` 없이 전환합니다. OpenCode를 재시작해 Magi를 선택하고 목표를 입력합니다. Git은 필수가 아니며 LLM 연결은 OpenCode에 별도로 설정합니다.
